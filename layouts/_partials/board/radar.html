{{- /* Terminal radar scope under the board, copied from the Stitch home-page study (stitch_strip_design_generator/code.html), not the design artboards. It sits in the left third of the row under the bays (.ops-row in home.html), where Stitch puts it. Contacts are the strips in the bays named by params.radar.bays (ACTIVE by default). Stitch places each target by hand with top/left percentages. Hugo has no layout engine, so each position is computed here instead: contacts are spread evenly round the scope in callsign order, and a hash of the callsign adds a little angle jitter and picks the range. The same content gives the same picture on every build, with no JavaScript. A contact on the right half has its label on the left of the dot so it stays inside the screen. Stitch labels each target with an invented flight level (API-02 / FL330); here the label is the callsign and the strip's type label, which are real. The scope repeats the bay, so it is hidden from assistive technology and its links are out of the tab order; the strips carry the same links. A visually hidden line gives the contact count instead. */ -}} {{- $cfg := site.Params.radar | default dict }} {{- if ne (string (index $cfg "enable")) "false" }} {{- $want := slice }} {{- range (index $cfg "bays" | default (slice "ACTIVE")) }}{{ $want = $want | append (upper .) }}{{ end }} {{- $contacts := slice }} {{- $labels := slice }} {{- range .bays }} {{- if in $want .name }} {{- $contacts = $contacts | append .strips }} {{- $labels = $labels | append (T (printf "status%s" .name) | default .name) }} {{- end }} {{- end }} {{- $contacts = sort $contacts "Params.callsign" }} {{- $n := len $contacts }} {{- $bayLabel := delimit $labels " / " }}
